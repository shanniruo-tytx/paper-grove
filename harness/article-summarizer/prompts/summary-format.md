# 非论文知识资料 · 总结格式（summary-format）

用于 **公众号技术解读 / 综述 / 论坛帖 / 官方文档 / 纯文本** 等非论文性质材料的统一总结。
**不使用** 论文拆解模板（不写「论文信息 / 论文 Story / 作者想回答的问题」那套），
直接把**核心内容 + 技术细节**抽出来，方便日后在「知识资料」里检索与复用。

> 原则：重事实、重数字、重可迁移点；带批判性视角（局限/争议必写）；不替原文夸大到临床结论。

---

## 推荐结构（按需裁剪，但 #0 元信息、核心观点、关键数据、局限 四节必留）

```markdown

kind: resource

journal: <出处名>
authors: [<作者或机构>]
```

## 各节写法要点

- **一句话概括**（frontmatter 字段，必写，**硬约束**）：标题旁的电梯演讲，一句话（≤140 字）说清「这是什么 / 解决什么问题 / 为什么值得记」，写在 frontmatter 的 `一句话概括:` 字段里（与 `summary` 摘要字段分开、互不影响）。前端主表格/卡片会把它作为小字显示在标题下方——这就是你看到的「标题旁的一句话解析」。本字段由 build 的 lint_kb 闸门强制校验——缺 `一句话概括` 字段则构建失败，所以**每篇总结型条目都必须有**。
- **一段话看懂**（置顶，必写）：用一段连贯文字把「大致内容 / 背景 / 做了什么 / 为什么做 / 怎么做的」串起来，逻辑通顺即可；本块只讲事实与脉络，**不讨论创新性、不展开批判性分析**（批判性见 #6）。目的是让读者 10 秒抓住主线，细节留给后面各节。
- **#0 元信息**：让用户 3 秒判断「这值不值得读」。来源类型从枚举里选；主题领域用逗号分隔的短词。
- **#1 核心观点**：不是段落摘抄，是「文章到底在主张什么」的要点清单。每条独立可读。
- **#2 技术要点**：这是和论文拆解最大的区别——**不写论文背景故事**，直接拆技术。
  子标题按真实技术维度取（数据构造 / 模型 / 评测 / 训练策略…），原文没涉及的维度删掉。
- **#3 关键数据**：非论文材料最容易被「读完即忘」的就是数字。所有规模、分数、对比、SOTA 差距都进表。
  务必标注对比口径（开源 vs 闭源、平均分 vs 分项），避免被误读成「全面超越」。
- **#4 方法/流程**：原文有管线/架构/步骤才写；纯观点文可省。
- **#5 定位**：综述/解读类必写——它相对已有工作的差异、补了什么空白。
- **#6 局限**：**必写**。非论文材料常见「标题党式结论」，必须把原文的边界、未验证处、作者自陈的局限列出来。
- **#7 可迁移**：把「和我们（翻译效率预测 / 多物种基础模型 / 实验室方向）有什么关系」显式写出来，资料才真正可用。
- **#8 术语表**：原文抛了陌生缩写/概念时补，方便日后速查。

## 反模式（不要做）
- 不要套「论文信息 / 论文 Story / 作者想回答的问题」模板。
- 不要把博主的解读当成论文结论；区分「论文说」与「博主说」。
- 不要遗漏分数对比的口径（开源/闭源、平均/分项），否则数字会误导。
- 不要为了凑结构硬写空节；没有就删节，但 #0 / #1 / #3 / #6 保留。
